L'image est l'oeuvre ; le NFT est le token auquel elle est assiciee

Creer une image(avec un 42) avec un numero(identifiant)
Stocker cette image sur IFPS et aussi 
Fiche de descprition de l'image = les metadonnées(titre,auteur,lien vers l'image)
Le certificat numeroté de l'image = le NFT , identifié par son tokenId dans un contrat
Le registre public des certificats et propriétaires = la blockchain
Le programme qui applique les règles du registre = le smart contrat

Objectif:
Creer une image - preparer sa fiche descriptive - programmer le registre
inscrire le NFT sur le blockchain de test

BNB Smart Chain Testnet
└── Contrat NFT
    └── NFT n° 1
        ├── Propriétaire : adresse de ton wallet
        └── Référence vers les métadonnées sur IPFS
            └── Référence vers ton image sur IPFS

Le but du projet est de créer ton propre NFT et de comprendre toute la chaîne :
1. Tu crées une image contenant 42 : c’est ton œuvre.
2. Tu stockes cette image sur un système distribué, comme IPFS.
3. Tu prépares sa fiche descriptive, appelée métadonnées : titre comprenant 42, ton login comme artiste et lien vers l’image.
4. Tu développes et déploies un contrat sur une blockchain de test.
5. Tu crées ton NFT avec ce contrat : il possède un identifiant, un propriétaire et une référence vers les métadonnées.
Le résultat attendu est donc : un NFT associé à ton image, dont tu peux vérifier le propriétaire et afficher l’œuvre.

COMPRENDRE tokenURI() ET LES DEUX DÉCODAGES

J'appelle tokenURI(tokenId) depuis le contrat chargé dans Remix, en indiquant
le numéro d'un NFT existant. C'est une lecture : aucune transaction à confirmer
dans MetaMask et aucun frais de gas à payer pour cet appel de lecture.
MetaMask sert notamment à signer et confirmer le déploiement et le mint.

Dans cette nouvelle version, le code déployé contient le dessin SVG et les
informations descriptives. tokenURI() les assemble et renvoie une seule chaîne :

data:application/json;base64,JSON_ENCODE

Premier décodage :
- Je prends uniquement la partie après la première virgule et je la décode
  en Base64 dans le terminal.
- J'obtiens le JSON avec name, artist, description et image.
- Le champ image contient lui-même : data:image/svg+xml;base64,SVG_ENCODE.

Deuxième décodage :
- La partie après la virgule du champ image représente le texte du dessin SVG.
- Le navigateur peut effectuer ce décodage et afficher le dessin directement
  lorsque j'ouvre la valeur complète du champ image avec son préfixe data:.

Schéma :
tokenURI(tokenId)
  -> JSON encodé en Base64
  -> décodage : métadonnées contenant le champ image
  -> image SVG encodée en Base64 dans ce champ
  -> décodage par le navigateur : dessin affiché

Les métadonnées ET l'image proviennent donc du contrat, sans récupérer
de fichier sur IPFS. Le PNG en fond du site n'est pas l'image de ce NFT.

Pour ouvrir l'image :
- Dans la barre d'adresse du navigateur, taper manuellement :
  data:image/svg+xml;base64,
- Coller immédiatement après la partie Base64 commençant par PHN2Zy,
  sans espace ni guillemets, puis appuyer sur Entrée.
- Un collage interprété comme une recherche affichait une réponse d'IA avec
  des erreurs supposées. Les données vérifiées n'avaient pas ces anomalies.
- Pour ouvrir l'extension MetaMask depuis le site, cliquer sur le renard orange
  dans la barre du navigateur ; l'icône puzzle ouvre le menu des extensions.
